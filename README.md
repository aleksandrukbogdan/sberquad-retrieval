# Поиск абзаца-ответа на SberQuAD

Измеряется одна стадия поиска: по вопросу нужно вернуть абзац, в котором размечен ответ. Генерация ответа и диалоговый RAG в замер не входят. На фиксированном срезе из 500 вопросов сопоставлены разреженный поиск, два плотных кодировщика, реципрокное слияние рангов, линейная и нейросетевая вторая стадия, а также подстановка гипотетического абзаца вместо вопроса. Обучаемые веса моделей не обновлялись. Скалярные параметры первой и второй стадии выбраны на 200 вопросах train и после этого не менялись.

Основной количественный итог такой. Лемматизация поднимает MRR@10 BM25 с 0.8903 до 0.9454 и обгоняет оба плотных кодировщика. Кросс-энкодер `bge-reranker-v2-m3`, поставленный на ту же голову из 20 кандидатов, что и русский MS MARCO-энкодер, поднимает MRR@10 с 0.9337 до 0.9690. Замена генератора HyDE с `Qwen2.5-0.5B` на `Qwen3-8B` поднимает MRR@10 с 0.7206 до 0.7841; вектор исходного вопроса по-прежнему сильнее вектора гипотезы. Числа сняты с `reports/dev.json`. CI сверяет таблицу с этим файлом до четырёх знаков: правка цифры без пересчёта отчёта роняет сборку.

При одном релевантном абзаце recall@k есть доля вопросов, где он попал в топ-k. MRR@10 — среднее `1/ранг`, ранг вне первой десятки даёт ноль. nDCG@10 использует обычный дисконт `1/log2(ранг+1)` и нормировку на идеальный список. При одном релевантном документе MRR и nDCG смотрят на одно и то же место; nDCG штрафует промах слабее.

## Постановка и корпус

Источник — SberQuAD (Efimov, Chertok, Boytsov, Braslavski, 2020, DOI `10.1007/978-3-030-58219-7_1`). Раздача DeepPavlov `sber_squad-v1.1.tar.gz`, sha256 `f407957da59fd998385df97c73cb82306bf91ece1998da6381df5144f20db128`. Короткий адрес из загрузчика Hugging Face вернул HTTP 204 без тела, поэтому архив взят с `files.deeppavlov.ai`. Тексты абзацев — Википедия, CC BY-SA. Вопросы — разметка SDSJ 2017. Официальный test ответов не содержит и в замер не входит. Опубликованный dev содержит 5036 вопросов; в таблице используется выборка 500.

В архиве одна статья-обёртка `SberChallenge`: заголовков Википедии нет, документ равен абзацу. Повторы текста склеены по sha256. В полном dev остаётся 3951 уникальный абзац. Идентификатор вопроса сохранён из файла. Релевантность — ровно тот абзац, в котором размечен ответ. Повтор строки ответа в другом абзаце релевантным не считается. Спан выравнивается по offset разметки: часть строк отличается регистром или хвостовой пунктуацией, для окон берётся выровненный интервал.

Срез зафиксирован в `data/splits.json`. Генератор — `random.Random(42)`. Файл после первой сборки не пересобирается.

- Подбор параметров: 200 вопросов train и 1196 абзацев (золотые абзацы этих вопросов плюс 1000 случайных абзацев из остального train).
- Отчётная таблица: 500 вопросов dev и все 3951 уникальных абзаца dev.
- Идентификаторы train и dev не пересекаются.

Вопросы SberQuAD написаны разметчиками по уже известному абзацу, поэтому лексическое пересечение высокое. На поиске по нормативным текстам разреженный поиск выглядел бы слабее. Корпус таблицы — абзацы dev, не открытый веб. ГОСТы не использовались: у них нет независимой разметки релевантности, а у части текстов ограничительная лицензия.

## Протокол

Seed 42. Сетка на train-200 максимизирует MRR@10, при равенстве — recall@10, затем меньшие значения параметров. После записи верхней ячейки `lab/config.json` помечается `frozen`, и `run_dev` этот файл только читает. Промпт HyDE по dev не подбирался.

На train подбирались `k1`, `b`, константа и глубина RRF, глубина второй стадии и четыре веса линейного реранкера. Знак логита кросс-энкодера проверен на 30 парах train и в сетку не входил. Плотные модели, реранкер и генераторы взяты готовыми ревизиями; дообучение в работе отсутствует.

Дополнительные строки считались отдельной командой `python -m lab.eval --split extra`. Она дописывает системы в уже существующий `reports/dev.json` и не пересчитывает верхние восемь. Для них взяты уже зафиксированные `k1=1.2`, `b=0.75`, `k=10`, глубина слияния 50 и глубина второй стадии 20. Инструкции моделей, которых в основном прогоне не было, взяты из карточек моделей и на срезе не настраивались.

Эмбеддинги e5 основного прогона прочитаны из кэша CPU-прогона. Кросс-энкодер DiTy и все дополнительные нейросети считались на NVIDIA H100 PCIe. BGE-M3 и Qwen3-8B — в float16. Реранкер BGE прошёл тем же циклом классификации, что и DiTy.

## Методы основного прогона

Токенизация общая: нижний регистр, `ё→е`, шаблон `[а-яa-z0-9]+`. Стеммера в основном прогоне нет. Это сделано сознательно: морфологический промах должен был остаться видимым, а не спрятаться внутри предобработки.

**bm25.** Okapi в варианте Lucene, свой инвертированный индекс.

```
idf = log(1 + (N - df + 0.5) / (df + 0.5))
tf' = tf * (k1 + 1) / (tf + k1 * (1 - b + b * dl / avgdl))
```

Повтор токена в запросе терм не усиливает. На train сетка `k1` ∈ {0.6, 1.2, 1.8, 2.0}, `b` ∈ {0.3, 0.5, 0.75, 1.0} дала MRR@10 в диапазоне 0.930–0.940. Верхняя ячейка — `k1=1.2`, `b=0.75`, MRR 0.9400. Соседние `b=0.3` и `b=0.5` при том же `k1` дают 0.9396. Сетка плоская. Зафиксирована верхняя ячейка.

**dense.** `intfloat/multilingual-e5-small`, ревизия `614241f622f53c4eeff9890bdc4f31cfecc418b3`. Mean pooling по маске и L2 написаны в `lab/models.py`. Поиск — произведение матриц и `argpartition`, без FAISS: 3951 вектор размерности 384 этого не требуют. Префиксы `query: ` и `passage: ` взяты из карточки e5. На train префикс дал MRR 0.9062 против 0.9021 без него. В слияние пошёл вариант с префиксом.

**dense_no_prefix.** Те же веса и тексты, пустой префикс у вопроса и у абзаца. Строка измеряет префикс. На dev знак эффекта перевернулся: 0.8755 без префикса и 0.8724 с префиксом. Разница в третьем знаке. Строка в таблице оставлена.

**rrf.** Слияние топ-50 BM25 и топ-50 dense. Скор документа — сумма `1/(k+rank)` по тем спискам, где он есть. Ранг с единицы. Документ из одного списка получает один член. Величины исходных скоров формула не видит. На train перебирались `k` ∈ {10, 30, 60, 100} и глубина ∈ {20, 50, 100}. Верх — `k=10`, глубина 50, MRR 0.9499. При `k=60` и той же глубине MRR 0.944. Малая константа сильнее удерживает первое место. Тот же механизм виден в вопросе `16123`.

**rrf_linear.** Вторая стадия. Голова RRF из 20 документов пересортировывается линейной комбинацией четырёх признаков. Хвост остаётся за головой. Глубина 20 больше 10, поэтому метрики @10 целиком определяются реранкером. Признаки внутри головы приводятся min-max к отрезку [0, 1] по этой голове: скор BM25, косинус dense, доля униграмм вопроса в абзаце, доля биграмм. Веса искались на train в {0, 1, 2}, нулевая четвёрка отброшена. Зафиксировано `bm25=0`, `dense=2`, `unigram=1`, `bigram=0` (`lab/rerank_weights.json`). Нулевой вес BM25 означает, что внутри уже отобранных двадцати его скор разделял кандидатов хуже, чем покрытие слов. Глубина 20 на train дала MRR 0.971 против 0.965 на глубине 5 и 0.969 на глубине 50.

**rrf_ce.** Та же голова из 20. `DiTy/cross-encoder-russian-msmarco`, ревизия `9029bab08103ad171724b510d312befa5b476293`, загрузка `AutoModelForSequenceClassification`. На dev это 10 000 пар. Один логит берётся как есть, два класса — последний. На 30 парах train средний логит золотого абзаца 2.34, случайного −6.84, множитель знака +1. На train CE был чуть выше линейного реранкера (MRR 0.973 против 0.971). На dev линейный выше по MRR (0.9415 против 0.9337), CE выше по recall@5 (0.970 против 0.966).

**hyde.** В dense вместо вопроса подаётся абзац, сгенерированный по вопросу. Генератор `Qwen/Qwen2.5-0.5B-Instruct`, ревизия `7ae557604adf67be50417f59c2c2f167def9a775`, жадная генерация, не более 128 новых токенов. Промпт: «Напиши короткий абзац на русском, который отвечает на вопрос. Только абзац, без пояснений.» Тексты лежат в `data/cache/hyde.jsonl`. Индекс абзацев — тот же e5 с префиксом.

**hyde_mix.** Сумма вектора вопроса и вектора гипотезы, затем L2. Тот же индекс абзацев.

Окна в таблицу не входили. На train-200 BM25 по целому абзацу даёт MRR 0.940 при 1196 документах. Окно 200 символов с перекрытием 80 — MRR 0.794 при 7282 кусках, окно 400 — 0.860, окно 800 — 0.934. Ответы короткие: медиана 22 символа, максимум 128. При перекрытии 80 спан короче 81 символа всегда целиком попадает в какое-то окно, и разреза ответа на train-200 не было. Просадка окна 200 — потеря формулировки вопроса, которая остаётся в соседнем куске. Пример — вопрос `6062`. Полная сетка — `reports/tune.json`.

## Дополнительные системы

Все восемь строк ниже используют опубликованные настройки и уже замороженные скаляры. Повторный проход по dev ради подбора не делался.

**bm25_lib.** `rank_bm25` 0.2.2, класс `BM25Okapi`, те же токены, те же `k1` и `b`. Документы с нулевым скором в список не попадают, как и в собственном индексе. Формула библиотеки другая. Её idf равен `log((N-df+0.5)/(df+0.5))`; отрицательные значения заменяются на `0.25` от среднего idf. Повтор токена в запросе добавляет вклад терма ещё раз. Собственная реализация использует люценовский idf с единицей под логарифмом и считает тип запроса один раз. На срезе полные топ-10 совпали у 79 вопросов из 500 (доля 0.158). Ранг золотого абзаца внутри сохранённой десятки совпал у 485 из 500. MRR@10 совпал до четвёртого знака: 0.8903. Расхождение формул переставляет соседей и почти не двигает место релевантного абзаца.

**bm25_lemma.** Тот же собственный BM25 и те же `k1`, `b`. Токены вопроса и абзаца заменяются на `normal_form` первого разбора `pymorphy3`. Это обычная для русского поиска нормализация парадигмы: словоформы сводятся к лемме, чтобы падеж запроса и падеж абзаца совпали. Отдельный индекс «по падежам», где каждая грамматическая форма остаётся своим признаком, стандартным приёмом не является: именно падеж разводит совпадающие по смыслу токены. На всех 500 вопросах среза лемматизированный запрос отличается от поверхностного хотя бы одним токеном. MRR@10 вырастает с 0.8903 до 0.9454, recall@5 — с 0.9120 до 0.9780. Это сильнейшая первая стадия в таблице и выше обоих плотных кодировщиков по MRR. Разбор `pymorphy3` берёт наиболее вероятный разбор без контекста, поэтому омонимия остаётся.

**bge_m3.** `BAAI/bge-m3`, ревизия `5617a9f61b028005a4858fdac845db406aefb181`. Вектор — L2-нормированный CLS (`last_hidden_state[:, 0]`), не выход pooler. Инструкция к вопросу не добавлялась: для плотного режима карточка модели её не задаёт. Длина обрезания 512, как у e5. Модель умеет 8192 токена, но документ здесь — один абзац, и длинный контекст в сравнении не участвует. MRR@10 равен 0.8747 против 0.8724 у e5-small, recall@5 — 0.9460 против 0.9380. Четырёхкратная разница в размере кодировщика на этом срезе сдвигает MRR в третьем знаке.

**rrf_bge.** То же слияние, что у `rrf`, с заменой e5 на BGE-M3. `k=10`, глубина 50. MRR@10 0.9153 против 0.9136 у слияния с e5. Выигрыш плотного кодировщика почти целиком сохраняется и почти не усиливается.

**rrf_lemma.** Слияние лемматизированного BM25 и e5 с префиксом, те же `k` и глубина. Recall@10 достигает 0.9920, это максимум таблицы. MRR@10 равен 0.9309 и ниже, чем у лемматизированного BM25 в одиночку (0.9454). Малая константа RRF по-прежнему отдаёт предпочтение документу, который стоит высоко в обоих списках, и снимает часть уверенных первых мест разреженного поиска. После лемматизации этот обмен становится виден уже на средней метрике, а не только на отдельных вопросах.

**rrf_bge_rerank.** `BAAI/bge-reranker-v2-m3`, ревизия `953dc6f6f85a1b2dbfca4c34a2796e7dde08d41e`. Голова — те же 20 документов исходного RRF(BM25, e5), что у `rrf_ce` и `rrf_linear`. Меняется только скорер пары. На dev 10 000 пар. MRR@10 0.9690, recall@5 0.9820, recall@10 0.9860. Это лучший MRR в таблице. Относительно DiTy прирост MRR составляет 0.0353 при неизменном пуле кандидатов. Глубина 20 подобрана под линейный реранкер; для BGE она не пересматривалась.

**hyde_qwen3** и **hyde_qwen3_mix.** Тот же промпт, та же жадная схема, те же 128 токенов, тот же индекс e5 с префиксом. Генератор — `Qwen/Qwen3-8B`, ревизия `b968826d9c46dd6066d109eabc6255188de91218`. У шаблона чата выключен режим рассуждения (`enable_thinking=false`), иначе след рассуждения занял бы бюджет в 128 токенов. Пустых гипотез нет. Тексты — `data/cache/hyde_qwen3.jsonl`. MRR@10 гипотезы 0.7841 против 0.7206 у модели 0.5B. Смесь с вектором вопроса даёт 0.8755 и совпадает с `dense_no_prefix`, оставаясь на уровне прямого dense (0.8724) и ниже лемматизированного BM25. Более сильный генератор уменьшает провал HyDE и не делает гипотезу лучшим запросом, чем сам вопрос.

## Что из этого следует

На этом срезе узкое место поверхностного BM25 — словоизменение, а не константы `k1` и `b`. Сетка этих констант на train умещалась в одну сотую MRR, лемматизация на dev сдвинула MRR на 0.055. После неё разреженный поиск ставит нужный абзац первым чаще, чем e5-small и BGE-M3. Плотный поиск по-прежнему полезен там, где леммы недостаточно: recall@10 слияния лемм и e5 равен 0.9920, выше, чем у лемм самих по себе (0.9840). Платой оказывается MRR.

Слияние с `k=10` выигрывает у одиночных первых стадий, пока ни одна из них не доминирует на первом месте. Как только BM25 после лемматизации начинает доминировать, та же формула MRR снижает. Это согласуется с тем, что на train малый `k` победил `k=60`: формула бережёт одинокий первый ранг ровно до тех пор, пока согласие двух списков в середине пятёрки не оказывается тяжелее.

Вторая стадия двигает метрику сильнее смены кодировщика. Переход от e5-small к BGE-M3 меняет MRR dense на 0.0023. Переход от DiTy к `bge-reranker-v2-m3` на той же голове меняет MRR на 0.0353. Линейный реранкер с нулевым весом BM25 остаётся между ними по MRR (0.9415) и проигрывает обоим нейросетевым реранкерам по устойчивости на вопросах, где dense золотой абзац не видит.

HyDE на обеих моделях хуже прямого запроса. Ошибки 0.5B были и тематическими, и фактическими. Модель 8B часть фактических ошибок снимает, тематические срывы сохраняет. Смесь векторов страхует срыв, возвращая результат к уровню исходного dense, и выше этого уровня на срезе не поднимается.

Префикс e5 измерен и оказался меньше шума между train и dev. В слиянии он оставлен, потому что на train был выше и потому что так учили e5. Обратный знак на dev записан строкой `dense_no_prefix`, а не спрятан выбором лучшего варианта после просмотра dev.

## Разбор отдельных вопросов

Ранг — место золотого абзаца. Для основного прогона пустое место в ранних заметках означало отсутствие в топ-100. Для дополнительных систем в `reports/dev.json` сохранён топ-10, поэтому ниже для них указано место в этой десятке либо отсутствие в ней. Счётчики в конце раздела относятся к замороженным системам; полный список меток — `reports/failures.jsonl`.

`36099`. «Что относится к городским железным дорогам?» В абзаце «железная дорога», в вопросе «железным». Общих поверхностных токенов нет, BM25 абзац не возвращает. Dense и BGE-M3 ставят его первым. Лемматизация доводит золото до 4-го места и первым его не делает: после сведения парадигмы конкуренцию выигрывают другие абзацы с теми же леммами. Реранкер BGE возвращает первое место.

`10797`. «Какова длина Северного Полярного бассейна?» Ответ «10,6 тыс. км». Поверхностный BM25 ставит золото на 44-е место и первым берёт абзац про Енисей, где «длина» расписана в километрах. Леммы «северный», «полярный», «бассейн» возвращают золото на первое место. BGE-M3 ставит его вторым. Гипотеза Qwen3-8B называет длину «около 12 000 километров» и оставляет золото на 5-м месте; смесь с вектором вопроса поднимает его на первое.

`13310`. «Какая пленка была самой тиражируемой в 20-е годы ХХ века?» Ответ Kodak. Dense на 3-м месте, BGE-M3 на 1-м. Модель 0.5B написала про несуществующую «Плёнку Серебряный Крест», и золота в топ-100 hyde нет. Qwen3-8B пишет про «Кинопленку» (Kino-Plenka) советского производства. Факт по-прежнему выдуман, но вектор остаётся в теме киноплёнки, и золото оказывается на 3-м месте. Лемматизация этот вопрос не спасает: в топ-10 лемм его нет. Реранкер BGE ставит золото первым.

`18407`. «Когда во Франции ввели в обращение франк?» В абзаце 1795 год. Модель 0.5B ответила «в 1792 году»; dense был на 3-м месте, hyde на 15-м. Qwen3-8B называет 1795 год, и гипотеза ставит золото первым. Лемматизированный BM25 тоже ставит его первым: поверхностный индекс в топ-10 его не имел.

`22868`. «Что заметил Доминик Франсуа Араго?» BM25, dense и BGE-M3 все на первом месте. Модель 0.5B ушла в интернет в России, ранг золота у hyde был 68. Qwen3-8B остаётся вне темы абзаца и пишет, что лучи звёзд не искажаются атмосферой; золота в топ-10 гипотезы нет. Смесь с вектором вопроса возвращает первое место. Это тот же механизм, что у модели 0.5B: гипотеза может уничтожить уже найденный документ, а смесь ограничивает ущерб уровнем исходного запроса.

`16123`. «С чьей концепцией схожа концепция наполнения баз добровольцами?» BM25 ставит абзац про IMDb и вики первым, dense в топ-100 его не имеет. RRF с `k=10` поднимает наверх текст про неолиберализм: место 5 в BM25 и место 4 в dense. Согласие середины пятёрки тяжелее одинокого первого места, потому что в формуле нет величины скора. Золото падает на 3. Оба реранкера основного прогона и реранкер BGE возвращают его на 1. Лемматизированный BM25 оставляет первое место, слияние лемм с e5 опускает золото на 2-е.

`291`. «что было открыто на территории клуба?» BM25 первый: музей и библиотека на Уимблдоне. Dense этого абзаца в топ-100 нет. RRF ставит золото третьим и наверх вытаскивает основание крокетного клуба (BM25-ранг 2, dense-ранг 1). DiTy возвращает золото на 1. Линейный реранкер уводит его на 13: вес BM25 нулевой, а dense уверен в соседнем абзаце. Лемматизация здесь вредит и опускает золото с 1-го места на 3-е. Слияние лемм с e5 выносит его из топ-10. Реранкер BGE, видящий ту же исходную голову, возвращает первое место.

`6062`, train, окно 200. «Какой остров является крупнейшим островом, разделённым между странами?» По целому абзацу BM25 на первом месте, ответ «Новая Гвинея» внутри окна лежит. В окно не попали «крупнейшим» и «разделённым», и окно в топ-10 не входит. Таких промахов на train-200 одиннадцать. В отчётную таблицу окна не ставились: единица документа и размер корпуса там другие.

`17318`. «К чему приурочены съёмки?» Четыре токена, в золотом абзаце про фан-фильм совпадает одно. Вопрос подходит к любому абзацу про съёмки. В топ-10 его нет ни у одной системы таблицы, включая леммы, BGE-M3 и реранкер BGE. Таких вопросов у замороженных систем на dev пять.

Счётчики замороженного прогона на dev: 10 морфологических промахов BM25 при попадании dense в топ-10, 33 ухода HyDE, 17 случаев, где RRF наказывает одинокий первый ранг BM25, 5 вопросов мимо топ-10 у всех систем того прогона.

## Воспроизведение

Из корня каталога `rag`.

```bash
python -m lab.eval --split dev
python -m lab.eval --split tune
python -m lab.eval --split extra
python -m lab.eval --split mini --check
pytest -q
```

`make eval`, `make tune`, `make extra`, `make test`, `make mini` вызывают те же команды. `extra` требует `rank-bm25` и `pymorphy3` из `requirements-eval.txt` и уже собранный `reports/dev.json`. Повторный запуск пропускает системы, которые в отчёте уже есть.

`docker compose up --build` поднимает основной dev-прогон. Веса в образ не запекаются, кэш Hugging Face вынесен в volume. При видимой GPU модель садится на неё сама. Занятую карту следует скрыть через `CUDA_VISIBLE_DEVICES`.

На push CI гоняет pytest: ручные скоры BM25, RRF и nDCG, mini-корпус против `reports/mini_baseline.json`, пересчёт метрик из сохранённых ранжирований и сверку таблицы выше. Mini-корпус кодируется хеш-эмбеддингом из `lab/hashvec.py` и к числам таблицы отношения не имеет. Полный прогон с весами — `workflow_dispatch`, команда `python -m lab.eval --split dev`. Дополнительные системы в этот job не входят: их ранжирования уже лежат в `reports/dev.json` и проверяются пересчётом метрик.
